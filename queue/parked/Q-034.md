### Found (2026-11-27, fence 126)

`OWNED_PROCESS_CLOSE_TIMEOUT` comes only from `settledChild` (`scripts/smoke-full-app-windows.cjs`), the proof's 10 s wait for the console host to end. `closeBrowser` over its bound throws `BROWSER_SURVIVED_CLOSE` instead. The third application close, `closeApplication('BROWSER_')`, named its host wait `BROWSER_` + `CLOSE`, the same name as the browser close phase. So the browser close passed. The app's Ctrl+C close on the start that opened the default browser did not end the console host within 10 s. The failure line came about 11 s after `browserSeen` and `closes` holds 2 entries, which agrees. The console host waits up to 10 s after the app ends while anything in its job runs (`native/windows/ConsoleProof.cs`), and the browser the app opened is in that job. The log does not show whether the app itself ended or which process stayed. The cleanup's `APPLICATION` failure came 0.9 s later, so it was not the 10 s wait. Its code was not printed.

Done in PR (Q-034): the third close is `BROWSER_APP_` (a test fails when any close phase repeats another phase's name). On a host wait over its bound, the failure line prints `closeWait`: the time waited, whether the host's exit was seen, whether the app process and the tree it owned still run, and how many browser-image processes started after the snapshot still run (counts only). A browser close over its bound prints its time waited and the tree's counts. The cleanup line names each part's fixed code. The bounds are unchanged.
