### Owner's decision (chat, 2026-11-27)

"I'm good with agreeing to all their licenses to get this to work for us. Go ahead and ... bundle everything required instead of proposing." The owner accepts the CasparCG (GPL v3 or later), Mesa (MIT and its notices) and NDI SDK/runtime licence terms for bundling. No proposal is needed for the bundle/no-bundle choice. The owner believes every target PC has a GPU with OpenGL 4.5 but is not sure, so Mesa ships as a fallback.

### Success criteria

1. The Windows ZIP carries, at pinned versions with SHA-256 checked at build time (the pins in `docs/design/WINDOWS_OUTPUT_PROOF.md`): CasparCG Server 2.5.1 stable, Mesa 26.2.6 MinGW (x64 OpenGL files only), the NDI 6 runtime DLL (`Processing.NDI.Lib.x64.dll`, the version CI proves) and the Microsoft x64 VC++ runtime files Caspar needs (or its official redistributable, run by Setup only with the operator's consent). NDI Tools are not bundled. Nothing is downloaded at run time.
2. Licences: CasparCG's GPL text and a written offer or link to its exact corresponding source (tag v2.5.1-stable); Mesa's notices; the NDI SDK licence terms, the NDI trademark attribution and the ndi.video link that NDI's software-distribution page requires (read it at build time, quote what it requires in a design note); a `THIRD-PARTY-NOTICES.md` at the ZIP root listing each component, version, licence and SHA-256. `BUILD-MANIFEST.json` covers them.
3. Mesa's `opengl32.dll` must never sit beside the Caspar executable that uses the GPU (Windows would load it instead of the driver). Ship it in a separate folder; the renderer choice decides which Caspar layout runs.
4. An OpenGL check: Setup and Diagnose report whether this PC's GPU driver gives OpenGL 4.5 (fixed codes such as `GPU_OPENGL_45`, `GPU_OPENGL_TOO_OLD`, `GPU_OPENGL_UNKNOWN`; never the GPU name or driver path in shared evidence). The app uses the GPU when it does and the bundled Mesa software renderer when it does not, and says which (`renderer: gpu` or `software`) in Diagnose and on the Game Day Diagnostics panel. An explicit machine-file setting can force either. Hosted Windows CI has no GPU: it proves the software path and the check's too-old/unknown answer; the GPU path is a manual gate on a real PC, written as such.
5. The source-mode example and README/checklist point at the bundled components by default (no `<REPLACE>` for the NDI folder or the Caspar path); the parts list in the owner's spare-PC test plan becomes "nothing to install".
6. The extracted-ZIP Windows proof runs from the bundled components only (no separately installed Caspar, Mesa or NDI on the path) and still passes; every check green. Then a new evaluation build is recorded (commit, run, SHA-256) because the ZIP changed.
7. Not signed, not a release, not deployed. CasparCG's AMCP listener still binds every interface (WINDOWS_OUTPUT_PROOF.md › Security): do not change that here, but keep it in Open risks and the README's stadium warning.

Too big for one run: split into S parts first (the build skill).
