Kind: Fix

### What was seen (fence 70, review of Q-005, by reading only)

The page's own refresh is overtaken by a second refresh (another tab, or the activation proof). It answers `CATALOG_REFRESH_SUPERSEDED`, and the page reads status at once (`static/js/piraiders-game-day.js`, `refreshSource` then `sourceStatus(true)`). The newer refresh is still reading, so status shows no catalog. If an earlier refresh had succeeded, the catalog code is null and the page shows `CATALOG_UNAVAILABLE`. The 3 s status poll then does not adopt the newer catalog while `src.problem` is set, so the page may stay on "unavailable" until the operator clicks Refresh. The code before Q-005 ended in the same page state. Not reproduced.

### Success criteria

- A browser test reproduces the order (page refresh overtaken while a newer one reads, after an earlier good refresh) and shows what the page displays, or shows that it converges.
- If it does not converge on the newer catalog: a page fix, with the browser test failing without it. Original SPX controls untouched.
- No hang or false pass; `npm run test:browser` green.
