Title: wait-checks reports GREEN before every workflow of the commit has started
Kind: Fix
Area: Build
Size: S
Added: 2026-11-23
---

### What was seen (fence 69, PR #86)

`node scripts/builder/wait-checks.cjs <sha>` returned `GREEN 4 checks` on PR #86's head `9431ebf` while the Foundation checks and the full-app proof workflows were still queued (pending runs with no check runs yet). Those added six more checks later (10 in all). The script counts only check runs that exist, so a commit whose slower workflows have not created their jobs yet reads as green. Caught by hand before merging; nothing was merged on the false green.

### Success criteria

- wait-checks never prints GREEN while any workflow run for the commit (`actions/runs?head_sha=`) is queued, pending, waiting or in progress, or while a workflow that ran on the commit has created no check runs yet.
- A test with a stubbed API: four finished green check runs plus one queued workflow run reads RUNNING, not GREEN; the same after the workflow's jobs finish green reads GREEN.
- The land skill's step 6 is unchanged in meaning.
