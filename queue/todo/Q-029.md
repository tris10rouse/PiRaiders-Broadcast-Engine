### Found by Q-021 (fence 118)

The extracted-ZIP Windows proof, run from the ZIP's own components under a folder name with a character outside the ANSI code page, saw no NDI source (`PROBE_SOURCE_NOT_FOUND`, PR #137's first run, job 140494771530). CasparCG 2.5.1 (`src/modules/newtek/util/ndi.cpp`) loads `Processing.NDI.Lib.x64.dll` from its start folder first (a wide path) and only then from `getenv("NDI_RUNTIME_DIR_V6")`, read as narrow text, which loses such a folder name. Q-021 placed the DLL in the software mirror beside its `casparcg.exe`. The GPU path still runs `runtime/caspar/casparcg.exe` with only the variable, so the same folder name would give no NDI output there.
