Title: Corrupt reused snapshot refused until the app restarts
Kind: Fix
Area: Exchange
Size: S
Added: 2026-11-26
---

### Found by 5c-4 (fence 80), outside that row

With the exchange folder present, a button prepared once and then prepared again by the same app reuses the snapshot the source coordinator staged (`exchange-source-coordinator.cjs`, `lastPrepared` reuse when the playback fingerprint is the same). If that snapshot's bytes changed on disk, the cache loader refuses it (`CACHE_CHANGED`, now shown by the diagnostics), but `lastPrepared` stays, so every later preparation of that button in the same app is refused the same way; only an app restart (a new coordinator) stages a fresh snapshot. Reproduced on Linux with `tests/game-day-recovery.test.cjs`'s third test plus one more prepare (still `PREPARE_FAILED`).

### Success criteria (written 2026-11-26, fence 80, before the work)

Decide and test one of: a refused reuse drops `lastPrepared` so the next preparation stages fresh from the source (the refused snapshot is never played and the refusal is still named once), or the refusal stays until restart and the diagnostics or page say a restart is needed. A test fails on the old code. No change to admission, the cache format or the exchange contract.
