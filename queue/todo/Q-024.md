### Owner's request (chat, 2026-11-27)

"I want the testing process to be easier." Asked which testing, the owner chose the one-click bench test: "Add a Test-PiRaiders.cmd that verifies the ZIP, makes the ids and a demo exchange folder itself, runs Setup/Diagnose/Launch, and prints one PASS/FAIL summary you can paste back. Hand-editing only for the real stadium exchange."

### Success criteria

1. A new `Test-PiRaiders.cmd` at the extracted ZIP's root, taking no arguments (refuses any with a plain sentence and exit 2, as the other four entries do). It never touches an existing `app\config\piraiders-app.json`, `app\config.json`, SPX installation or real exchange folder: it works only in its own new folder inside the extracted folder (for example `bench-test\`), and says so in its first line.
2. In order, each step's fixed code printed as it finishes: Verify (the same check as `Verify-PiRaiders.cmd`); a synthetic demo exchange folder written from the repository's sanitized fixtures (no operator content, no real feed id); a source-mode machine file for that folder with two new random v4 store ids made by the script (no `<REPLACE>`, no `New-Guid` by hand); Setup; Diagnose; Launch with `--no-browser`; approve, prepare and activate the demo button for a window that starts now, play slides 1 to 2, Stop black, close, each checked through the app's own routes; then Diagnose again (`app: not-running`).
3. One last line: `PASS` or `FAIL`, the failing step's name and code, and the path of one plain-text summary file to send back. The summary holds fixed codes, counts and timings only: no paths, ids, user or PC names (the privacy rules the proofs already use). Exit 0 on PASS, 1 on FAIL.
4. Everything it started is closed when it ends, also on FAIL and on Ctrl+C. A second run starts clean (it removes only its own `bench-test\` folder).
5. Clear about what it proves: it is a bench check of this PC with demo data, not the stadium, not the board, not on air; "NDI sender running" is not "received". The summary says so in one line.
6. OPERATOR-CHECKLIST.md and README-WINDOWS.md start with "Quick test: run Test-PiRaiders.cmd" and keep the 11 manual steps for the real exchange; BUILD-MANIFEST.json covers the new files.
7. Linux tests of the steps with stand-ins; the Foundation checks' Windows job runs `Test-PiRaiders.cmd` from the extracted ZIP and requires PASS; every check green.
8. Not signed, not a release, not deployed.

Too big for one run: split into S parts first (the build skill). Best built after Q-022 (and Q-023) so it tests the bundled CasparCG, Mesa and NDI runtime.
