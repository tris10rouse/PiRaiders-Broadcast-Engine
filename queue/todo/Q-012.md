### Found by Q-011 (2026-11-26, fence 95)

The test-bench NDI SDK receiver (`native/windows/NdiProbe.cs`) has a fixed lifetime, `GlobalDeadlineMs = 8 * 60 * 1000`; past it every request fails `PROBE_DEADLINE`, the receiver stops listening and exits 1. The four-hour soak (`scripts/smoke-soak-windows.cjs`) keeps one receiver for the whole run, so it cannot pass: the first run (job 139965117507) lost the receiver at about 480 s, between cycle 7's Stop and cycle 8's Launch (`PROBE_CONNECTION`, close failed). Probable cause, from the code and that run's timings; not confirmed by a recorded exit (Q-011 now records it).

### Success criteria (written 2026-11-26, fence 95, before the work)

The soak job's receiver lives for the whole planned run plus its close (bounded, at most the soak's own five-hour ceiling plus a margin); every other proof keeps the 8-minute default; the lifetime is set by the job, checked on both sides (a bad value fails closed), and a Linux test fails without the change. Never loosen the 5e-1 rules or the 20 s picture bound. The receiver is compiled and run only on hosted Windows: the five-cycle check run on the pull request is the Windows evidence. Then 5e-3 runs again.
