# ADR 0006: Isolated local session for managed native slideshow output

Status: Accepted engineering increment; implementation/CI verification recorded in the checkpoint and PR. No production deployment or hardware claim.

Use a loopback-only Node HTTP/Socket.IO host for the managed slideshow session, reusing the existing native SPX slideshow template, renderer, image validation and state controller. Keep original SPX controller, projects/rundowns, native lifecycle and OGraf on their existing paths. The host is a small transport/authorization boundary, not a replacement graphics engine. It starts no CasparCG/NDI process and provides no audience controls.

An isolated local origin avoids inheriting upstream broad static/CORS/session routing for private prepared media. Bootstrap credentials travel only in the initial fragment and authorization header, then disappear from browser history; private random cookie authentication protects exact registered images and socket admission. Origins, peer addresses and bounded requests/operations are checked explicitly. Cookies are not port scoped, so cookie names are randomized per host and same-site cross-port requests are rejected. Future launcher/producer integration must pass the program URL privately and redact credentials from logs.

One program renderer confirms initial black before readiness. Show/black operations resolve only after the native browser renderer confirms paint; cancellation retains the existing controller barrier until acknowledgment, disconnect or deadline. A session failure fences pending work, marks presentation unverified and replaces the controller with a stopped instance. There is no automatic replay/reconnect; explicitly reopening a credential URL and Launch are required. This host accepts only trusted Node action strings; arbitrary browser commands and caller cancellation signals are excluded from its public API. Stop/close/timeouts pair cancellation with black or teardown, avoiding an unsupported promise of rollback after a distributed commit/ACK race.

Default SPX/launcher behavior stays unchanged in this increment. Candidate preparation/Reload orchestration, audience feedback forwarding, RossTalk command mapping/priority, window/event wiring, producer loading and persistent diagnostics remain separate work. Real Chromium and loopback tests prove software behavior only; CasparCG CEF/NDI and receiver/on-air evidence require separate validation. Full wire contract: [presentation protocol](../design/PRESENTATION_PROTOCOL.md).
