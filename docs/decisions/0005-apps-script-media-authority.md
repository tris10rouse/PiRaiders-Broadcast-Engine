# ADR 0005: Apps Script owns media meaning; the Engine consumes ordered references

Status: accepted design direction from the owner's supplied media-library architecture. Source: Apps Script media storage document for version 2.122.0, November 13, 2026. **Corrected 2026-11-19:** the scheduler has since reached 2.159.0 and has published an exchange contract, draft 0.3.1, with four JSON schemas and a synthetic fixture pack. Where this record and that contract differ, the contract governs. Neither side is enabled: the scheduler's publisher exists as code and fixtures only and does not yet write an exchange folder, and the Engine's exchange modules are not wired into the default application. See docs/design/APPS_SCRIPT_MEDIA_CONTRACT.md for provenance, exact layout/table meanings and remaining contract gates.

The Apps Script workbook is authoritative for school year, event membership, Board-button grouping and occurrence sequence. Inside the source, Drive IDs join rows to bytes across renames/moves and Event Files File Keys identify distinct occurrences. In the exchange (corrected 2026-11-19), each occurrence names an asset by key and each asset is a content-addressed file verified by byte length and SHA-256; source file identifiers travel as metadata only, and a recurring button's occurrence carries the button's key with a null file key. Folder names are source-managed organization, not the relationship database. Apps Script remains the sole Sheet writer and owner of source rules/Slides conversion/tidy/undo. The Engine defaults to read-only source access and separate local immutable candidates.

Keep generic local-folder staging and schema-1 snapshots compatible. Add an explicit ordered exchange provider that resolves bytes by content hash under the configured exchange input root, never by source file identifier, path or name (corrected 2026-11-19; the earlier wording was "ID-aware byte resolution"); do not silently reinterpret folder-derived identities/order. Preserve repeated occurrences even if byte content is shared. Require complete validated selected decks before explicit Reload activation; keep active/last-good content on failure. On Board/Loaded For remain source statuses, not Engine/NDI/receiver/on-air evidence. Private scripts/PDFs/crew data stay out of the default audience-media projection.

The supplied document established storage semantics only. The exchange contract, draft 0.3.1, now defines what it left open (corrected 2026-11-19): an explicit position for every occurrence, a five-part selection identity that carries the target board key and the button identity, event and broadcast-window instants with their sources, and delivery through a shared synced folder. It is a draft, not frozen and not deployed; do not add fields it does not define. The scheduler changes numbered R-158 and R-168 have been built and released in its source (R-168 in 2.130.0; R-158 across 2.139.0 to 2.149.0). The Engine still depends on no particular scheduler release being installed, only on the exchange contract. No Drive/Sheet actions or source-app modifications are authorized by adopting the reference document.

This extends the SPX-first architecture. It neither replaces SPX HTML/OGraf/projects/rundowns/lifecycle nor changes CasparCG/window/NDI policy. Rendering and local/fixture work can proceed while the source export contract is specified.
