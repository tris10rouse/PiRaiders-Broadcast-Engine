# Full-application Windows output proof

Status: implementation prepared; actual final-commit Windows execution is required. This is a software integration proof, not an evaluation release or hardware approval.

## Acceptance

Run the actual `piraiders-app.cjs --no-browser` entry with its default native boundaries. Its JobHost owns actual SPX; Game Day's default manager owns the nested event JobHost and real Caspar/CEF/private Console/NDI sender. No fake service, injected spawner, runtime factory, preload or policy clock replaces that chain. Playwright operates the actual page/session/CSRF endpoints; real allowlisted loopback RossTalk exercises the shared command path. A real SDK receiver verifies fresh1080p30 frames with the exact stable source identity.

The disposable synthetic fixture must prove:

- Preparation and activation through Game Day before the fixed future window; no observed sender before start, with native birth-time validation at the boundary. The short proof explicitly configures prewarm0; existing scheduling tests retain default15-minute coverage.
- PNG/JPEG playback, Next/Previous wraps, successful Reload, corrupt Reload refusal with last-good pixels, Auto/Manual wiring and sustained full-frame Stop black while the same sender root remains alive.
- Identity-verified Caspar root crash, old generations gone, source-independent cached recovery, fresh stopped black and explicit Launch before recovered output.
- Original real-clock window end, sender-generation cleanup, drained receiver silence/zero connections and actual SPX remaining available. Policy observation is bounded at end+20s and tree observation at end+30s, with lateness recorded; these are proof deadlines, not a product latency guarantee.
- A second active event followed by actual CLI parent death, complete recorded nested-tree removal, receiver silence and unchanged SPX configuration.

## Evidence and privacy

Retain only synthetic received PNGs, actual workstation screenshots and sanitized result JSON with final SHA, component hashes, explicit environment, source-identity hash, fixed phases/counts and actual timing. Never retain raw native output, fixture configs, private producer URLs, credentials, operator records or component binaries. The known private URL pattern is scanned in bounded UTF8/UTF16 runtime/component/SPX text files; this is a supplemental pattern scan, not proof of an adversarial filesystem sandbox.

Generation captures require exact PID/decimal creation ticks/image and chronological ancestry. Incomplete fresh live observations remain unknown and cannot satisfy cleanup; malformed or contradictory identities fail closed. Uncertainty may only be retried within the original bounded deadline. Cleanup fallback may target only a still-matching recorded owned JobHost and cannot turn a failed assertion into a pass.

## Environment and release boundaries

The workflow inherits exactly `GALLIUM_DRIVER=llvmpipe`, `LIBGL_ALWAYS_SOFTWARE=1` and `MESA_GL_VERSION_OVERRIDE=4.5COMPAT` through the real parent. Pinned Mesa remains app-local; the existing pinned NDI runtime installation is disposable CI only. This tests default process wiring under that explicit environment. An evaluation launcher still needs reproducible component/environment setup; the proof alone does not supply it.

This increment does not test extracted-package output, default Windows browser dispatch or graceful full-output application close. It also leaves independent native deadline enforcement for a frozen SPX event loop, source exchange import, preflight/diagnostics, soak and nonproduction installation instructions as release gates. Windows10 target, external LAN receivers, Daktronics routing and stadium hardware remain unverified. No signing, formal release, binary redistribution or production deployment follows.
