# Detached raw catalog receipt gate

BE-006 needs an accepted catalog fact even when a selected manifest or its images have not arrived. `createExchangeCatalogReceiptGate().validate({feedBytes,catalogBytes,expectedBinding})` validates the complete feed/catalog documents independently of a selected event, school year, current pointer, manifest or asset. It adds no source reader, journal write, Game Day integration, cache action, timing approval or output admission. Every result remains `ready:false` and `semanticValidation:pending`.

## Exact bytes and trust

The argument envelope and explicit `{feedId,epoch}` binding use strict own-data-property checks before values are read. Both raw inputs must be Buffers. The gate immediately makes bounded owned copies using actual TypedArray slots rather than caller-supplied length/buffer/offset accessors or copy/toJSON methods. Parsing and SHA256 use the same owned copies. Returned parsed documents and digests are deeply frozen; mutable raw Buffers are not exposed. Later caller mutation cannot change the receipt. This is an ordinary in-process Buffer boundary, not protection against hostile proxies, concurrently written shared backing memory or compromised JavaScript globals/processes.

The feed limit is64KiB and catalog limit5MiB, both inclusive. Existing `parseExchangeJSON` retains fatal UTF8, no BOM, decoded duplicate-key rejection, safe nonnegative integer domain, paired-surrogate, depth32 and300000-node limits. Whole catalogs do not pass through the1MiB fingerprint canonicalizer. Only individual schema-bounded selection entries and identity tuples use existing canonicalization/hash helpers. The separate source canonicalizer limit is unchanged.

Factory initialization loads the existing pinned local schema registry and Ajv backend. This reads the fixed local schema resources; it does not access source/media/network paths. Per-call validation performs no filesystem or network operations. Backend initialization failure throws only `CATALOG_RECEIPT_BACKEND_UNAVAILABLE`; per-input failures return fixed codes without paths, source values, raw parser/Ajv errors or stacks. Parsed successful receipts contain source-sensitive metadata and are internal data, not public diagnostics. The gate verifies bytes/context, not publisher cryptographic authenticity.

## Accepted catalog scope

Both complete schemas must pass with the existing no-coercion/default/removal policy. Feed and catalog must match the explicitly approved feed UUID/epoch. Header-only, foreign or schema-invalid documents cannot yield a receipt. For every catalog entry, the gate checks its tuple-derived selection ID, root school year, enclosing event key, target board and origin. Event-origin target must equal that event's board; null event boards map to the legal empty tuple board. Season selections retain their own nonempty target board and template button identity, which can differ from the event board. Display labels are not normalized or substituted for event tuple identity.

Generation epoch, sequence and metadata-fingerprint prefix must agree with the inherited root/entry values. Manifest path must equal the exact literal selection/generation path. This checks descriptor syntax and available context before a future reader opens anything; it does not prove filesystem confinement or read the named manifest. Advertised manifest/fingerprint hashes remain unverified against actual manifest content until the selected-manifest gates run.

Repeated entries with the same selection ID, tuple and identical full entry data are accepted. Different full entry data for one ID is rejected as ambiguous catalog data, including differences in informational displayLabel, labelShared or occurrenceCount. This comparison covers more than contract4.7's descriptor fields. It is a conservative admission policy, not a schema uniqueness requirement or a claim that V16 mandates rejecting those informational differences. Contract2.1's different-tuple collision is rejected by tuple/hash checks. No global event-key uniqueness rule is invented. The existing selected metadata reader still rejects repeated selected IDs; aligning that separate reader with identical repeats is future integration work.

The gate does not infer readiness from manifestState, occurrenceCount, eligibility or timing summaries, and adds no new relationships among those fields beyond their schemas. Empty catalogs, omission, changed school years, unresolved event boards, incomplete summaries and tombstones remain metadata. Source calendar/Chicago eligibility and timing admission still need the selected verified manifest and later operator confirmation. A receipt cannot cause Stop, delete a last-good deck or reset a sequence floor.

## Receipt and future coordination

Success returns an immutable `receipt` with validated-catalog scope, approved feed/epoch, catalogSequence, computed exact delivered feed/catalog digests and parsed documents. Raw whitespace remains part of the digest; semantically equal JSON with different whitespace has different bytes. The result does not contain a committed journal event or active-cache state.

A future coordinator may translate a successfully completed receipt into a catalog fact and append it through the separately verified journal. The raw gate is stateless and does not itself enforce monotonic counters. Existing metadata capture still returns only a completed selected-manifest pin; this change does not add `captureCatalog()`. A shared-flight reader integration must privately hand off exact raw bytes, preserve immutable deadlines/late completion/close fences and journal only after successful completion, not from callbacks during capture. Later full capture must validate and reconcile its own catalog bytes again; an earlier receipt cannot bless a different later catalog.

## Verification and limits

Synthetic tests cover strict envelopes/Buffer accessors, ownership after mutation, exact whitespace hashes, binding and nested full-schema failures, descriptor context/generation/path failures, season and unresolved-board cases, Unicode identities, identical/conflicting repeats, malformed JSON and parser bounds. A valid catalog with2000 real descriptors exceeds1MiB while remaining below5MiB; its equivalent object still fails the unchanged source canonicalizer. Exact padded raw limits are also exercised.

One composed test writes actual temporary feed/catalog files with no selected manifest. Existing full capture fails without a last pin, while the raw receipt supplies a catalog fact to an actual local journal. After reopen, changed valid catalog bytes at the same sequence are rejected and the original floor remains. This is receipt/journal independence evidence, not a new reader method or full59-step fixture acceptance.

Root must run full regression and final-SHA Windows CI before merge. Linux composition does not establish Windows storage, Drive Desktop placeholder/hydration/offline behavior, licensed component setup or stadium compatibility. No private fixture scripts are executed or private fixture trees published. Rollback removes this unused module/test/document without altering source data, caches or existing output services.
