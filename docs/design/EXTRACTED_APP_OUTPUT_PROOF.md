# Extracted Windows application output proof

## Acceptance

Build a genuine committed-source Windows development ZIP, verify its original inventory, and launch its unmodified root CMD with bundled Node. Actual SPX/Game Day, default prepared-event runtime, packaged JobHost and external pinned Caspar/NDI must perform the same eleven received-frame scenarios as the checkout proof: initial black, PNG/JPEG navigation/wrap, successful and rejected Reload, sustained Stop-black with sender alive, offline sender crash recovery, fresh stopped-black/explicit Launch, real production-window retirement and active CLI-parent-death cleanup.

Run the source and extracted scenarios as independent Windows Actions jobs with the same internal deadlines. Caspar/Mesa/NDI remain separately prepared CI-only components outside the ZIP. The application receives the fixed machine-owned `caspar.rendererProfile: mesa-llvmpipe-compat`; inherited Mesa variables (including Windows case variants), Node preloads, npm variables and system Node PATH entries are removed from the actual app process. Received pixels therefore exercise application-owned renderer configuration. Requested profile/environment is not an independently recorded GL_RENDERER value.

## Location and ownership evidence

The extracted location descriptor is constructed only after original `verifyManifest` succeeds. Its root CMD, bundled Node, app entry, SPX and JobHost paths must be inventoried. Expected source SHA must match the artifact manifest; actual bundled Node version must match its metadata. Hash the ZIP before extraction and after, and retain archive/manifest hashes, source SHA, Node version and original inventory count in sanitized proof evidence.

PowerShell launches the unmodified CMD inside a benchmark JobHost and deliberately remains alive after the application exits. Paths enter PowerShell only as environment data. Capture the unique canonical bundled CLI generation, distinct from SPX, and the held outer PowerShell generation using PID/creation/image identities. Resolve both sides of packaged image comparisons, including physical/Windows namespace aliases; never fall back to a basename. Kill the verified actual CLI, require all its captured nested generations confirmed gone with no unknowns, and positively require the outer benchmark still alive through receiver silence and endpoint loss. Only then may cleanup close the outer fallback. This prevents outer containment from masking a broken inner lifetime boundary.

## Inventory and privacy

Record/freeze the original sorted inventory and manifest hash before creating any synthetic configuration. Check every original file's type, size and SHA256 afterward, including every path component's link status. The original manifest bytes/hash must remain unchanged. New synthetic configuration/cache/log files are permitted but never promoted into or represented as original inventory entries. Never regenerate the inventory.

Use synthetic media/configuration only. Keep the private producer capability out of logs and evidence. Proof output contains fixed categories, hashes, counts, versions and synthetic PNGs; it never copies original operator or Apps Script fixture data. The tested ZIP/checksum is still a development artifact.

## Explicit limits

Portable tests validate inventory mutation/link refusal, descriptor membership, case-insensitive environment removal, exact inner/outer ownership, image alias handling and private-capability scans. Those are not Windows execution evidence. Final Windows source and extracted-output jobs must pass at the final SHA before merge, together with existing SPX/OGraf, package, native-window, Caspar/Console and NDI regressions.

The proof does not establish clean-machine licensed component setup, default Windows browser dispatch, graceful app close, real target sleep, Windows10, LAN/NDI receiver interoperability, Daktronics/DMP/stadium compatibility or evaluation-release readiness. No production installation, network change, system-clock manipulation or live equipment interaction occurs.
