# Native slideshow output surface

Mode: Experience. Passive audience program output, extending the established SPX surface under the [approved controller brief](CONTROLLER_BRIEF.md). This is a surface-specific record of the renderer in `ASSETS/templates/piraiders/slideshow/`, not a new visual identity or operator dashboard.

The first viewport is a full-frame black canvas with a decoded, aspect-contained image. No heading, controls, source paths, version label or developer status belongs on program output. At 1920×1080 the image retains its native aspect; scaled 16:9 workstation preview retains composition. Canvas and both image layers use `#000`; images use `object-fit: contain`. The two layers support cut/default and configurable linear fade (one-second default when selected). Pending or failed candidates retain the last committed image. Transition exceptions, animation cancellation and stalled paint reject with fixed error codes; a watchdog bounds transition/paint completion at the selected duration plus 1000 ms. Stop cancels pending work and clears image and feedback to black.

Pinned AUTO/MANUAL feedback uses white text and a 1 px white border over a black backplate. The whole element reaches 75% opacity, including border and backplate. Its actual font stack is `Arial, Helvetica, sans-serif`, sized `clamp(10px, 1.25vw, 32px)` (24 px at HD), with line-height 1 and padding `.4167em .6667em`. Position is right `2.5vw`, bottom `4.444vh`. Motion rises 12 px at HD over 300 ms, holds 1000 ms and fades over 300 ms; rise distance scales with surface height.

Reload sits above mode feedback at bottom `10.7vh`, sharing the right inset and a small black backplate. Its font is `clamp(9px, 1.04167vw, 27px)`; the white ring rotates every 800 ms. `RELOAD FAILED` clears after 1800 ms. Initial feedback waits for the first frame commit; feedback stays hidden while black. These are audience graphics, not buttons; keyboard, focus and hover controls belong to the future workstation interface and do not apply to this passive output.

The template receives explicit trusted frame/feedback updates from a future presentation adapter. It owns no slideshow navigation or auto timer, no source catalog, and no NDI process. Image URLs must remain within the same-origin media namespace; no arbitrary external/Drive/private-document URL rendering. The namespace is an integration contract, not an already implemented media-serving route. Existing SPX templates, controller CSS and OGraf assets stay untouched.

Verification recorded 13 passing real Chromium tests with zero skips, including image decoding, fade midpoint, loading/failure retention, feedback timing, transition failure recovery and Stop races. Captures at 1920×1080 and 960×540 include white-image feedback, portrait containment and native HTML/OGraf regressions. Synthetic PNG/JPEG images are test fixtures. The [capture provenance](../../build/browser-artifacts/provenance.json) records Chromium 156 on Linux, base HEAD `8114cb5e3e20bb7aee96cdf4b82ad5bce8028881`, a dirty local tree and five source-file hashes; all five match the source checked for this documentation pass. This is working-tree evidence, not proof of a clean published commit. No tests or captures were rerun for this documentation update.

Two finish reviews returned ship: the second narrowly confirmed the functional recovery fix; neither reported material visual findings. The shipped reviewer definition and CLI context were unavailable, so existing project context and fresh independent review under the review packet were used; no detector result is claimed. Windows/Ubuntu CI for this increment remains pending. Browser evidence does not establish CasparCG CEF, NDI, receiver, stadium hardware compatibility or first-release readiness. This extension preserves the incumbent SPX controller, existing templates and OGraf assets; it does not redefine the global design system.
