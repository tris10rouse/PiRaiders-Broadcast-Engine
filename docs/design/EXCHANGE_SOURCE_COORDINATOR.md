# Detached exchange source preparation (BE-006)

`createExchangeSourceCoordinator({sourceRoot, cacheDir, journalDir, storeId, binding:{feedId,epoch}, timeoutMs?})` composes the existing reader, validators, journal and ordered snapshot importer. It is not connected to Game Day, profiles, output or production-window policy. Its methods are `refreshCatalog`, `inspectSelection(identityTuple)`, `prepareSelection(identityTuple)`, `snapshot` and `close`. Each operation optionally accepts an AbortSignal. Timeout is 10–60000ms; individual metadata captures retain their 30000ms cap.

The journal must already exist with the separately retained store UUID and explicitly approved feed/epoch binding. Opening never initializes or rebinds it. Source/journal and source/cache configured paths cannot overlap in either direction. Actual resolved source/journal locations are also compared before source capture and before each append, including Windows case aliases. A missing source fails before facts. These are observed filesystem boundaries, not atomic privileged-writer protection. Requests and tuples are owned synchronously before asynchronous work. The optional second constructor argument is a trusted code-only test seam, never source or machine JSON configuration.

## Metadata and content boundaries

Each flight independently validates and journals a catalog receipt before attempting the selected manifest. A fresh combined capture then reconciles its own same-byte catalog receipt, even if it differs from the earlier capture. Present documents pass full schemas; selected metadata passes the integrity, fingerprint, problem-state and timing chain. The strict V9 selected-admission boundary requires current.json and rejects a catalog descriptor newer than current. Verified current-ahead remains permitted: the publisher commits current before catalog. Missing/older current cannot advance manifest facts or prepared content; independently valid catalog facts remain. Before recording a manifest fact, data-only checks enforce asset/occurrence counts, per-image bytes/dimensions/pixel product, consistent physical aliases and the 512MiB sum across unique assetKey rows. Actual images may still be absent. Catalog and manifest facts use exact delivered digests and separate revision/head-hash CAS operations. Conflicts and uncertain acknowledgements fail closed without retry loops.

Only complete, nonempty, problem-free content reaches the actual length/hash/full-decode ordered importer. Accepted metadata and prepared content are separate. Empty, incomplete, removed, omitted, corrupt or unavailable source data cannot replace previous prepared content or delete its cache. No method calls Stop, replaces a controller deck, resets a playback timer or changes an active window.

Matching feed/epoch/selection and verified playback fingerprint reuses the previous snapshot UUID/path after full offline verification. It does not reopen source image files or restage content. A corrupt cached image rejects reuse and preserves the prior reference; this does not claim the corrupted bytes remain usable. Changed playback stages a fresh immutable UUID while keeping previous caches. Cache identity is not the Reload decision: verified playback fingerprint is.

All results carry `scope:source-preparation`, `ready:false` and `operatorConfirmationRequired:true`. Timing is only a proposal. `admissionEligible` reports validated source policy, not runtime permission. Complete content may be cached while source eligibility is false; future arming must separately require eligibility and an operator-confirmed window. Existing active output must not be blacked by source ineligibility. No source-button-to-RossTalk deck mapping is invented here.

## Cancellation and physical ownership

One physical slot covers journal I/O, captures and actual reader close, staging/loading, decoder termination and cleanup. Reader logical timeout may precede actual close; the coordinator checks reader busy state every5ms and keeps its slot while any orphan remains. Logical timeout, close or caller abort returns promptly and fences late candidate acknowledgement. Physical cleanup remains the BUSY barrier. Immutable monotonic deadline checks also run after synchronous gates and directly before publishing accepted/prepared references.

A journal write started before cancellation may remain a valid metadata fact. A snapshot already published before cancellation may remain an unacknowledged immutable directory. Neither is activated or deleted by the coordinator; there is no rollback or general power-loss guarantee. Existing journal storage/observed filesystem limits still apply.
