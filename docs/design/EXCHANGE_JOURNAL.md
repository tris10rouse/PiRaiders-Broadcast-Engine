# Detached local exchange journal

BE-006 adds a local persistence boundary around the pure ledger transition model. This module is unused by Game Day, Drive capture, media staging, caches, scheduling and output. It accepts trusted validated facts, not arbitrary source documents. Every result is `ready:false`; a journal acknowledgement never means playable, eligible, armed, receiving or on-air.

## API and initialization

`createExchangeJournal()` returns `initialize(directory,storeId)`, `open(directory,expectedStoreId)` and `append(directory,{expectedStoreId,expectedRevision,expectedHeadSha256,event})`. The UUID is supplied and retained by trusted machine configuration outside the journal, not discovered and silently trusted from whichever directory appears. Configuration persistence and UI approval are future integration work. An error result contains a fixed code, scope and non-readiness; no source values, paths or exception stack are echoed.

Initialize requires an absent dedicated directory and uses exclusive mkdir. It publishes a genesis record with the configured UUID. Concurrent initializers cannot both own the directory. A crash or failure before complete initialization leaves an existing incomplete directory: opening fails, and initialization refuses to reset it. Recovery or deliberate replacement requires a separate explicit policy; this module never repairs by deleting history. Open-existing never creates any directory or file. A missing initialized store is a failure, not an empty ledger.

The caller must supply a stable approved absolute local directory outside Drive-synced trees, source media and public HTTP paths. Normalized absolute paths are required; observed directory ancestors, the final store directory, record files and private temporary files reject symbolic-link/junction substitution. UNC roots are rejected on Windows. These are observed filesystem checks, not atomic protection against a privileged process replacing ancestors during I/O. Filesystem suitability and ACL ownership still need integration/preflight validation; no stadium machine is touched.

## Records and publication

Committed names are fixed twelve-digit zero-based revision filenames. Revision0 is genesis; later records contain only schema version, kind, store UUID, revision, exact previous-record raw-byte SHA256 and one ledger event. They contain no mutable head, supplied snapshot, active cache or output action. Records are deterministic canonical JSON plus one LF. Replay checks exact canonical bytes, which also rejects duplicate-key, BOM, malformed UTF8 and noncanonical documents, then validates strict record fields and the complete contiguous parent hash chain. Each event must produce one actual changed transition through the pure ledger. No-change observations do not append a record.

Append snapshots its checked request and event before asynchronous I/O. It replays stored history itself and requires both the caller's expected revision and exact raw parent SHA. It never accepts a caller-supplied plan/state as proof. A complete bounded record is written to a random private filename using wx, file-synced and closed. `fs.link` publishes it to the fixed next-revision filename with atomic no-overwrite semantics. Concurrent writers starting from one parent can both prepare candidates, but exactly one can create the next filename. EEXIST is a conflict; callers must reopen and reconsider. There is no rename/copy overwrite fallback or PID-only lock stealing.

Before acknowledgement, the committed record is reopened and its exact digest verified. A write, sync or close failure before publication produces no success acknowledgement. Any non-EEXIST error from the link call is conservatively `JOURNAL_COMMIT_UNCERTAIN`: a filesystem call can take effect and still report failure. Post-publication/readback failure is also uncertain. Reopen is required; an uncertain operation never authorizes downstream admission. No failure path deletes a committed filename. Cleanup removes only this invocation's successfully created private temporary name; failed wx creation cannot delete someone else's collision file. Cleanup failure may leave an ignored private temporary file while a successfully verified commit remains acknowledged.

File sync, atomic link and process-crash/reopen tests establish a limited process-failure boundary. There is no directory flush or general power-loss guarantee. A complete valid-prefix backup rollback, full store replacement plus changed configuration, administrator modification, disk/firmware failure or malicious noncooperating writer is not prevented by a hash chain. An external trusted high-water anchor would be needed for stronger rollback detection. No authentication or tamper-proof storage claim is made.

## Bounds and failure behavior

Defaults cap committed history at10000 records,96KiB per record and64MiB aggregate committed bytes, plus32 recognized v4 UUID private temporary filenames, each at most96KiB. Unknown names, directories, symlinks, oversized temporary files, gaps, missing genesis, unsupported records, invalid transitions and hash/store mismatches fail closed. Nothing is silently evicted, truncated or reset. The factory permits only lower test/resource bounds, not raising these maxima. Retained temps have a finite count/size budget; persistent leftovers eventually require explicit diagnostic/recovery work rather than automatic destructive collection.

Replay performs bounded full history validation and repeated pure transitions. It is not a real-time event admission path or a performance claim at maximum history/state size; replay latency and an explicit maintenance policy remain integration work. The source canonicalizer's1MiB budget remains unchanged; individual journal records are smaller. The `io` and `phase` factory options are trusted test seams, not plugin or untrusted source extension points.

## Evidence required

Portable tests execute actual filesystem links, distinct competing child-process initializers and appenders, exact winner-state/hash verification, and real child termination at empty temporary creation, partial write, complete write, sync, closed pre-link and published pre-ack barriers. Reopen must yield only the old complete prefix or new complete record. Narrow injected write/sync/close/link/readback/cleanup failures test acknowledgement boundaries, including an actual link followed by an exception. Other cases cover corrupt/gapped/noncanonical history, UUID substitution, missing/incomplete stores, strict bounds, nested caller mutation during I/O and path substitution.

Local execution is Linux evidence only. The same cases must pass on actual Windows Actions before merge; no mocked test establishes NTFS behavior. Clean-machine target Windows10/sleep, full power-loss, cloud/Drive/localadmin resistance and stadium hardware compatibility remain unverified. Full stateful59-step source fixture acceptance, independently validated catalog receipts, verified assets and immutable schema2 cache integration are separate next work. Rollback removes this unused module/test/document without touching source data, caches or existing output services.
