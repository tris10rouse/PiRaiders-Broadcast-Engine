# Managed RossTalk integration contract

BE-003 increment joins the real TCP bridge to the existing managed presentation host. It opens no live stadium connection; caller explicitly starts a listener. Default launcher remains unchanged.

## Priority transport extension

`new RossTalkBridge(config,{handleCommand,prioritizeStop:true,allowEphemeral})` opts into priority Stop; existing callers retain FIFO behavior and default limits. Validate prioritizeStop as boolean. In priority mode allow handlerTimeoutMs50..300000 (legacy50..10000, default2000 unchanged). No source/framing/map/reply-buffer weakening.

Admit valid Stop before normal queue capacity. Cancel queued normal requests, abort/logically settle active normal request, retain its actual callback barrier and original independent watchdog. Start one Stop callback alongside at most one interrupted normal. Repeated Stops share that one callback/outcome while Stop or orphan remains; retain at most maxQueue extra reply followers, reject excess without additional callback. A later normal command cannot run until both physical callbacks settle; repeated Stop clears any newly queued normal work. Timeout of orphan remains terminal even after successful black. Close remains bounded and late callbacks cannot restart dispatch or double counters.

Priority-mode normal BUSY rejects need not close input: keep parsing bounded frames so a following Stop in the same burst remains reachable. Silent fire-and-forget EOF may close its socket immediately while retaining accepted command metadata. Invalid framing/source/filter/reply-buffer errors keep existing fail-closed behavior; an unaccepted command on a closed connection has no delivery guarantee. Default FIFO mode behavior stays unchanged.

## Owned presentation facade

`await createRossTalkSession({presentation,rossTalk,canControl,resolvePreparedSnapshot,resolverTimeoutMs:5000},{allowEphemeral:false})` creates/owns a presentation host and priority bridge. Expose only `{origin,getProgramURL,start,address,snapshot,close}`; program URL is credential-bearing and must never be logged. presentation is the existing createPresentationHost configuration; rossTalk is the existing normalized transport configuration. Both callbacks are mandatory functions. canControl must return literal true synchronously; false/throw/promise fails closed (consume rejected promises). resolvePreparedSnapshot({signal}) resolves only an absolute already-prepared snapshot directory, not source staging or Google access. Return-path validation occurs before activation.

Capture facade generation and renderer epoch before resolving Reload. Recheck signal, literal gate, generation and epoch immediately before host.reloadSnapshot. Stop always bypasses the playback gate, increments generation, aborts resolver and requests host.dispatch('stop') immediately. A stopped/unready host still cancels any preparation; false result is a failed command, never an OK. Map all !ok presentation results into rejected callback completion, keeping fixed sanitized facade lastError diagnostics. Browser clients never send control commands.

Resolver timeout (100..120000) aborts it and requests black, but does NOT release a callback that ignores cancellation. Await its actual settlement or the transport's terminal deadline; no successor around unresolved work. Any transport abort independently requests Stop/teardown; host dispatch accepts strings, not caller signals. A terminal transport fault closes owned presentation/bridge boundedly and leaves the facade faulted. Close cancels/fences resolver and closes both; no private exceptions/tokens in results or diagnostics. Use one shared Stop operation per facade to avoid extra side effects from abort/fault/repeated Stop paths.

Before binding, derive/validate an end-to-end handler budget covering resolverTimeoutMs + prepareTimeoutMs + at least three*(commandTimeoutMs+500) +1000ms; default facade derives it from owned host settings. Explicit lower handlerTimeout fails; any budget above300000 fails closed. Do not pretend arbitrary external congestion guarantees completion. Facade owns the host so independent Node callers cannot bypass command ordering. Direct callback deadlines remain terminal. The gate validates command eligibility only; sender lifetime is still enforced independently by LauncherRuntime and must never wait for these callbacks at window end.

Snapshot is frozen `{state,lastError,transport:<bridge snapshot>,presentation:<host snapshot>}` without URL/credentials/raw callback/network errors. Listener is off until start; factory failure cleans up its owned host. No public browser HTTP control endpoint, no source scan, no network/firewall or production equipment changes. Hardware sender/NDI evidence remains separate from actual TCP/browser verification.
