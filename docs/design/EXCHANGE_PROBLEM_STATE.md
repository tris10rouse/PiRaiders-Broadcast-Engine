# Detached exchange problem-state gate

The draft0.3.1 schema and selection-integrity gates leave relational state/problem rules open. `scripts/lib/exchange-problem-state.cjs` adds only the selected-manifest V5 rules and the explicitly scoped V20 selection-level null-problem rule, together with the normative5.2 BOARD and bounded selection-limit semantics. It remains detached from Game Day, preparation, byte staging, cache publication, output, timers and arming.

## Composition and scope

`createExchangeProblemStateGate().validate(manifest)` first makes an owned bounded JSON snapshot through the existing canonicalizer. It then requires the existing structural and selection-integrity gates to pass. No source-selected schema, new dependency, network loader or image read is added. Bundled schema initialization retains its existing static resource reads. The API accepts decoded JSON; bounded JSON normalization is not a sandbox for arbitrary hostile JavaScript proxies or modified host globals.

Schemas already enforce the closed problem/detail sets, numeric bounds, required problem fields, origin-dependent field shapes, complete/empty/removed array conditions and the bounded diagnostic's incomplete/empty-arrays/exact-one-problem shape. The existing integrity gate checks identity, order, references, paths and recomputed fingerprints. This module does not repeat those implementations.

The added rules are:

| Area | Relational check |
|---|---|
| Ordinary incomplete (V5) | At least one null-asset occurrence has a problem inline or associated through its occurrence key in the summary list. The bounded limit diagnostic is a separate exception. |
| V20 selection-level null-key scope | A summary entry with `occurrenceKey: null` is only BOARD_UNRESOLVED or a bounded selection-limit diagnostic. Per-image LIMIT_EXCEEDED/dimensions or pixels stays row-level. This is a named subset, not allV20. |
| BOARD_UNRESOLVED (2.1,2.3,5.2) | Event origin only; incomplete; every retained row has a null asset and inline BOARD_UNRESOLVED problem; no assets; exactly one BOARD_UNRESOLVED summary with null occurrence key. Schemas enforce detail:null. A blank board on an active complete/incomplete event selection must satisfy this pattern. |
| Selection-limit diagnostic (5.2,5.6) | `limit` equals500 for occurrences/assets, or536870912 for unique total bytes, and `observed` is strictly greater. Selection-limit details never appear inline on an occurrence. |

## Deliberately preserved representations

V20 permits listed **or** inline problems. The module does not require every inline problem to be duplicated in the summary, summary order, summary uniqueness or identical duplicated representations. It does not invent a blanket rejection of unknown non-null summary references; the stated V5 check requires an actual failed occurrence association. More extensive problem-association guarantees must be agreed from the contract before claiming them.

The source contract's BOARD authority is2.1/2.3/5.2;3.2 is the publisher's revision ledger. The gate checks the normative BOARD pattern when that problem is advertised and enforces the forward blank-active-event-board rule. It does not infer the converse that every BOARD_UNRESOLVED code requires a null board key; that converse is not separately specified. Empty/removed metadata keeps its existing arrays-empty form. Neither is an instruction to Stop, cancel, delete or extend a production window.

The selection-limit branch is evaluated before BOARD handling. An over-limit diagnostic intentionally has no occurrences/assets, so the ordinary incomplete row requirement must not reject it. No order between source BOARD detection and source count checks is inferred. `assets` diagnostics remain legal even though the fixture publisher normally reaches the occurrence limit first. `observed` can be any safe integer above the cap, not only cap+1. The consumer cannot reconstruct or verify discarded source rows or the diagnostic's actual observed source count; it verifies the declared policy and consistent diagnostic shape. Catalog occurrenceCount/descriptor binding remains a separate envelope boundary.

## Results, errors and non-readiness

Results are immutable and always carry `ready: false`, `semanticValidation: pending` and `scope: selection-problem-state`. Success labels V5, V20-selection-null-problem-scope and the two specific5.2 checks. It does not claim allV20 or fullV1–V20 acceptance. Failures return fixed codes for input, prerequisite validation, state, scope, BOARD or limit policy. Raw Ajv errors, source strings, paths, stack traces and underlying exception messages are not returned. Failure does not modify the supplied manifest or the metadata reader's last pin.

Pending areas remain explicit: calendar/window validation, actual asset bytes/hash/full decode/aggregate staging, durable feed/sequence/rebind state, eligibility/admission and external descriptor context. The existing eligibility schema already enforces false exactly for CANCELLED/FINISHED and permits informational TENTATIVE; this is not arming authorization. Existing full date-time/schema checks do not establish Chicago offset/DST round trips, valid interval order or maximum window duration. No automatic source selection, Reload, Stop, timer reset or activation occurs.
