# PC source catalog pages (BE-006 prerequisite)

This is a backend for the approved school-year → event → resolved board/button selector. It does not install the screen, configure a source, approve a window, prepare media, or start output. The existing local-manual catalog and its128-entry policy remain distinct.

`createExchangeCatalogReceiptGate().validate(...)` now brands its frozen receipt in a module-private WeakSet. `isExchangeCatalogReceipt(receipt)` recognizes only that exact object; a clone/spread/parsed copy is not a validated receipt. Branding proves this gate's validation, not machine approval, current source eligibility or content readiness. Reader/coordinator freezing preserves receipt identity.

The receipt validator also reconciles repeated event keys: metadata excluding selections must agree; identical selection descriptors deduplicate; the merged event must contain at most100 unique selection IDs. Conflicting event headers/selection descriptors or combined overflow fail with the existing CATALOG_RECEIPT_CONTEXT_INVALID. Source labels never act as identity.

`createExchangeCatalogView(receipt)` accepts only a branded receipt and returns frozen `summary()`, `eventsPage(query)` and `selectionsPage(query)`. Revision is SHA256 of feed UUID, epoch, catalog sequence and BOTH original delivered document digests. The whole catalog is never passed through the source canonicalizer's1MiB budget; validated catalog input retains its separate5MiB cap. The view retains source order and full labels/tuples, with exact-key Maps (including Unicode and prototype-looking event keys). Source800-event/100-selection bounds remain unchanged.

Queries are strict ordinary data records: `{revision,offset?,limit?}` and `{revision,eventKey,offset?,limit?}`. Revision is required; offsets are safe nonnegative integers within the selected collection; default page size50, permitted1..64. Unknown fields/accessors/invalid values are rejected without invoking getters. Event keys use the schema's64-codepoint bound, not64 UTF16 units. Results carry `ok`, `ready:false`, revision/binding/year/sequence, total/offset/limit/nextOffset and only whitelisted events or selections. A different valid revision yields CATALOG_REVISION_STALE. Missing events yield CATALOG_EVENT_MISSING. Invalid queries yield CATALOG_QUERY_INVALID. No source paths, manifest delivery paths, executables, private roots, raw receipts or playback capabilities are returned.

Event `timingProposal` and `eligibility` are source metadata. Neither is a confirmed production window or admission grant. Selection rows preserve ID, full five-part tuple, origin, target board, original display label, template key, generation, fingerprints and declared occurrence count/state. Counts and manifest state do not prove actual media availability. No labels are truncated or converted into machine event slugs.

The existing provider `refreshCatalog()` now derives a view only from its own successful journaled capture, verifies its configured feed/epoch, and returns the view summary as `catalog`. New synchronous methods are `catalogState()`, `catalogEventsPage(query)` and `catalogSelectionsPage(query)`. These page reads perform no I/O and require an available latest view. Busy provider returns BUSY; no view returns CATALOG_UNAVAILABLE; close returns PROVIDER_CLOSED. Refresh entry revokes the previous browse view before strict descriptor-safe options validation. All asynchronous failures leave it unavailable. A monotonic refresh-attempt fence prevents an earlier held success restoring authority after a newer request fails, including BUSY. A caller must explicitly refresh/retry; old revision pages cannot silently join new metadata.

Browsing reads feed/catalog only and performs no selected current/manifest/asset capture or stage. Physical source ownership, journal facts and provider deadline/drain behavior remain unchanged. Failed browse refresh does not enter active canControl, edit confirmed windows or request black. Existing runtime mandatory admission and changed-Reload guards remain separate.

The detached approval store is documented in EXCHANGE_APPROVAL_STORE.md. It stores explicit data only. Future PC/web integration must use authenticated local guards/CSRF, retained machine/store identities and canonical private-root policy; compile exact machine-owned runtime policy; reconcile source proposals without double-applying lead/prewarm; and recheck exact approvals at new admission. Merely saving a record is not authority. No automatic init/rebind/reset/approval is added.

Catalog regressions cover >1MiB real validated metadata with800 events,100 selections,200-codepoint labels, supplementary event keys, repeated labels/origins, conflicting duplicate headers, strict/stale queries, actual missing selected files, disconnected source, blocked reader/abort, invalid getter options and superseded refresh. Initial unsupported fixture seam failure is retained separately. All three review-found catalog bugs were reproduced before fixes. Approval composition initially compared insertion-order JSON and denied correctly; canonical exact-data comparison corrected that test helper, with original failure retained. Final full/Windows evidence belongs to the PR.

No frontend/rendering code changes here, so there is no new screenshot or whole-surface UI claim. Existing Windows/browser/native output CI remains required. Rollback removes the new browse APIs/projection and detached store, retaining local-manual behavior. This remains development work, not an evaluation release or Windows10/LAN/stadium compatibility claim.
