# Game Day integration after prepared-event runtime

Status: implementation plan. The trusted sender-only ownership option is the current small increment; the HTTP UI, application launcher and shared local admission described below are not implemented yet.

Recommendation: **host Game Day inside the persistent actual SPX server; let each event own only CasparCG, its private presentation host and RossTalk session.** The one Windows application launcher owns SPX for the whole application lifetime. Invalid/offline event media, preparation failures, window end and profile switching must never close SPX. Preserve the current standalone prepared-runtime/legacy launcher defaults for developer proofs.

## Ownership and smallest API change

Current `createPreparedEventRuntime()` stages before creating `LauncherRuntime`, which owns both SPX and CasparCG; its `close()` therefore stops SPX. Calling that factory unchanged per selected profile would duplicate/restart SPX. Do not use a fake child/no-op spawner to conceal this.

The ownership increment adds a **trusted Node option** such as `manageSpx: false` to `createPreparedEventRuntime()` and `LauncherRuntime`; default remains true. It must not be accepted from profile JSON or HTTP. With false, construct/start/stop/health-track only the Caspar supervisor; `this.spx` is absent, and close results are paired with actual owned service names rather than the current fixed `[spx, casparcg]` indexes. SPX spec in the existing strict profile can remain for compatibility, supplied by the host's machine configuration; it grants no event ownership. An eventual extracted sender-only class is sensible, but not prerequisite to the evaluation increment.

Add a small `GameDayManager` instantiated once by SPX. It holds one active event, at most one candidate preparation, a generation fence and a bounded operation queue. Factory/prepare errors become fixed manager status codes; they do not escape SPX startup or mutate its projects/rundowns. A candidate can stage without starting/binding; activation waits until the old runtime has fully closed. Never start a second sender or second RossTalk listener around an unresolved close. Initial UI should reject event/profile activation while a current production window is active; ordinary **Stop remains black with sender alive**, not event shutdown. Window expiry/confirmed inactive close permits the next profile. Closing the whole application may terminate owned jobs as already specified.

Current prepared API exposes only `start/snapshot/close`. Add a trusted local-command facade for Launch/Next/Previous/Auto/Manual/Reload/Stop. **Local UI and RossTalk must share one bounded admission/priority-Stop queue and the same generation/control gates.** Do not directly call `PresentationHost.dispatch()` beside `RossTalkBridge`'s queue: that would create two authorities. A narrow `RossTalkSession.dispatch(action)` plus bridge admission refactor is preferable; Stop must synchronously fence pending normal commands and preparation. Surface fixed results only.

## Configuration and persistent entry point

Add machine-local application configuration containing SPX port/cwd, fixed Caspar component paths, fixed NDI source name/runtime path (or explicit output-none), cache/runtime roots, and an allowlisted local profile catalog directory. Browser requests select **profile IDs**, not executable paths, arbitrary XML, producer URLs or filesystem callbacks. Compile the selected local/manual event fields into the existing strict profile using machine-owned SPX/Caspar/output policy. Keep the `local-lexical-v1` media contract separate from the unprovided Apps Script source/order contract. No Google API adapter or invented fields.

A new `scripts/piraiders-app.cjs` should supervise only bundled SPX under the existing JobHost; it must not also run legacy Caspar supervision. `Launch-PiRaiders.cmd` invokes that app entry (or an explicit new app mode), then opens `http://127.0.0.1:<port>/game-day`. Legacy `piraiders-launcher.cjs` remains available for old developer configurations. A trusted optional app-config path enables the server integration; starting normal `node server.js` without it retains upstream behavior. Missing/bad event profile or absent media shows an actionable Game Day state while SPX remains usable. Do not overwrite an existing SPX `config.json`/operator content to enable the new view.

Source: `server.js`, new `routes/routes-game-day.js`, new `scripts/lib/game-day-manager.cjs`, `scripts/lib/prepared-event-runtime.cjs`, `scripts/lib/launcher-runtime.cjs`, `scripts/lib/rosstalk-session.cjs`/`rosstalk-bridge.cjs`, new app entry, packaging template/bundle recipe/smoke.

## UI and HTTP security

Add a distinct `/game-day` view (`views/view-game-day.handlebars`, separate static JS/CSS) and an opt-in link in `views/partials/header.handlebars`. Keep `/shows`, `/gc`, native HTML/OGraf renderers, template imports, lifecycle controls and external SPX Caspar routes intact. This UI is for the workstation only; never expose it as an iPad workflow.

Keep new APIs below `/game-day/api/...`. Existing `server.js` has global permissive `cors()` **before** sessions/routes. Exclude every Game Day path variant accepted by Express from that middleware (including case/trailing slash variants), and explicitly reject Game Day OPTIONS/cross-origin requests. Keep existing SPX CORS behavior outside this namespace. Reuse SPX session/login checks when configured; initialize the new router after sessions. Existing bounded body parsers can stay if their 100KiB bound is documented; mutations must require JSON and strict small action-specific schemas, not form bodies.

For all new pages/state/media: require socket peer loopback (`127.0.0.1`, `::1` or mapped loopback), exact canonical Host `127.0.0.1:<configured-port>`, and reject a wrong Origin if present. Ignore proxy/forwarded-host claims. For every mutation require the exact Origin, same-origin Fetch Metadata when supplied, custom `X-PiRaiders-CSRF`, and a CSPRNG per-session synchronizer token checked in constant time. Put the token in the rendered page/meta or same-origin no-store response, never URLs, access logs, snapshots or profile files. Never accept originless state-changing browser calls. Keep global SPX cookie/login semantics intact; do not weaken existing authentication. Add `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `frame-ancestors 'none'`/DENY and a restrictive new-page CSP. Render text with escaping/textContent. Return fixed codes, sanitized state and request IDs; not raw exceptions, config, private paths or command lines.

The existing presentation host has a **private producer capability URL, cookie and exclusive renderer socket**. Never return/embed/open that URL in Game Day or reuse it as desktop preview; it could steal the actual Caspar renderer session and leak control capabilities. Initial view can show current index/deck/count and a separately authorized static input thumbnail, explicitly labeled selected media rather than measured program output. Report sender eligibility/running, renderer acknowledgement, decoded frame and receiver/board evidence as separate states. Current prepared `snapshot()` is already sanitized and a useful base; extend with bounded counts/can-control flags, not private origin/epoch/token.

## Minimal verified increments

1. Ownership option + shared local/RossTalk admission + manager tests: failed staging leaves SPX alive; profile replacement never duplicates SPX/sender/listener; pending close blocks activation; Stop/window end fences controls even around ignored asynchronous settlement.
2. Opt-in router/page in the **actual SPX server**. Real Playwright tests load `/game-day`, select catalog entries, handle missing/offline/corrupt media, verify disabled/loading/error/keyboard states, navigate back to actual `/shows` and seeded `/gc`, and assert native HTML/OGraf/template routes still work. Request tests cover LAN denial, Host/DNS rebinding, wrong/missing Origin, cross-site Fetch Metadata, missing/wrong CSRF, OPTIONS, JSON limits, arbitrary paths/actions and old generation requests. Test actual default SPX startup without app mode as a regression. Synthetic component hooks belong only to trusted Node test construction, never profile or environment-exposed production bypasses.
3. Extracted Windows artifact test invokes the same one entry, boots actual persistent SPX, proves the Game Day failure path cannot take it down, then runs a local/manual profile against the selected actual Caspar/private console and existing NDI receiver proof. Test closing the browser leaves services correctly supervised; closing app ends jobs. Verify page/profile changes and window end preserve SPX PID. Retain the tested component/NDI license and distribution constraints; do not silently bundle unapproved components.

Only after the functional local/manual UI/artifact passes these gates provide the first honest owner evaluation build with precise nonproduction installation/checklist, then pause automation. Preserve explicit remaining hardware/source-provider limits: receiver/board/on-air compatibility requires separately authorized off-air evidence, and the Apps Script adapter/schema is still unavailable.
