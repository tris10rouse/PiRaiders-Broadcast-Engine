# PiRaiders Windows development bundle

This unsigned development artifact is **not the first user-testable release**. It contains actual SPX, native HTML/EBU OGraf assets, locked production dependencies, bundled Windows x64 Node and the native JobHost. Its single root launcher now starts the persistent application parent and opens Game Day after verifying owned startup. Checked-out actual application output has separate passing Windows evidence; output from this extracted artifact and the broader release gates remain unverified. CasparCG, Mesa and NDI binaries are not included. Do not install on stadium equipment.

## Extract and configure a disposable workstation

No manual testing is requested from the project owner until an honest evaluation build is announced. For a developer bench, extract the entire ZIP into a new writable folder on nonproduction Windows x64; do not run inside the archive or overwrite an existing installation. No system Node/npm/PM2 or repository checkout is needed. Installed .NET Framework v4 is required for the containment host. Windows CI does not establish Windows10 target-PC or stadium compatibility.

Preserve `BUILD-MANIFEST.json`, the ZIP SHA-256 sidecar and all licenses. The unsigned manifest detects accidental drift, not download authenticity. Initial manifest verification must precede configuration: operator files and logs are intentionally absent from the original inventory.

1. Copy `app/config/piraiders-app.example.json` to `app/config/piraiders-app.json`. This is machine-owned local configuration, not the Apps Script exchange. Configure separate catalog/media/cache/runtime roots; keep source media separate from private cache/runtime paths. Refer to the source repository's Game Day backend contract before adding an event.
2. If starting a disposable new SPX bench, copy `app/config/spx-app.example.json` to `app/config.json` and create `app/DATAROOT`, `app/LOG` and `app/events`. If using existing SPX, preserve its configuration/data and point `spxConfigFile` at the intended app-relative file. The launcher requires a bounded existing configuration with a valid explicit port and never generates or rewrites it. The blank credentials in the example are for an isolated bench; existing SPX login/configuration policy controls access. This package changes no firewall or network settings.
3. The example has `output.type:none`, loopback-only RossTalk and no events. It starts SPX/Game Day without Caspar binaries; the empty catalog is expected. It cannot produce video merely by launching. Before event activation, separately prepare verified/legal CasparCG/Mesa/NDI components, configure the correct local paths and production window, and follow their documented setup. No runtime download/install or global driver change is performed by this ZIP. Do not bypass production-window supervision with an always-on sender.
4. Run `Launch-PiRaiders.cmd` from the extracted root. Spaces/Unicode and `!` in its folder path are supported. The fixed entry uses only bundled Node. Missing machine config fails before SPX starts; invalid SPX config/occupied foreign port fails safely. Optional `Launch-PiRaiders.cmd --no-browser` still verifies owned startup and prints the credential-free numeric-loopback Game Day URL. Other arguments are refused. No executable, path or schedule is accepted from this command line.
5. Keep the launcher console running. Closing the browser tab leaves SPX alive for the application lifetime. Game Day preserves original SPX projects/rundowns and native HTML/OGraf controls in the separate SPX Graphics workspace. The iPad operator never sees this UI. Event sender lifetime belongs to the configured production window; Stop means black while that sender remains permitted, not application exit.
6. Ctrl+C, Ctrl+Break and closing the console window each request the same bounded shutdown/retry (Windows gives a closed console only a few seconds; the native job still closes what is left when the Node parent ends). The console close is tested on Linux with a real SIGHUP; its hosted-Windows proof is part 5d-2. Closing or killing the actual Node parent independently closes its native job, including descendants. A reported close failure retains unknown ownership and requires diagnosis before restarting. Native PIDs identify containment hosts; local process/readiness status is distinct from renderer output, source discovery, receiver connection and board routing. Private native stdout/stderr is discarded; the console uses fixed lifecycle/error categories plus the local controller URL.

Its `app/config/piraiders-launcher.example.json` describes that legacy API only and is **not** read by the root launcher. Do not rename legacy config to machine config: they are different schemas. Passing smoke coverage starts the real bundled parent/HMAC/SPX/Game Day, reads its empty local catalog, preserves SPX config bytes, then kills the proven actual CLI parent and requires all captured CLI-owned process generations and the HTTP listener to disappear while the outer bench root is positively still alive (so its fallback cannot mask inner containment). Separate retained legacy smoke starts real bundled SPX plus an explicitly simulated AMCP service and verifies its production-window shutdown. Bundled worker full PNG/JPEG decode, immutable/offline staging and authenticated transport are also tested; presentation acknowledgments in those component cases remain simulated. No CasparCG/CEF/NDI frame or hardware result follows from this package smoke.

Output through the extracted full application, default browser-handler dispatch, reproducible legal component/Mesa setup, exchange importer, diagnostics/preflight/soak, clean-machine installation and an operator checklist remain release gates. The root launcher does not yet configure CI's explicit software-Mesa environment. Do not describe this ZIP as a user-testable build, formal release, signed installer or target-hardware certification. No live stadium, external LAN receiver, Daktronics/D8VIDEO-P/DMP routing or board input was tested by this package increment.

## Optional reference software renderer

An explicitly prepared Caspar/Mesa installation can opt in to the tested software renderer by adding `"rendererProfile": "mesa-llvmpipe-compat"` inside the machine configuration's `caspar` object. This optional machine policy is not accepted from event catalog rows. Omit it to retain the existing inherited environment and component behavior. Unknown profiles and arbitrary environment maps are rejected. The development example remains unchanged and does not require Mesa for its initial empty/output-none configuration.

The profile sets `GALLIUM_DRIVER=llvmpipe`, `LIBGL_ALWAYS_SOFTWARE=1` and `MESA_GL_VERSION_OVERRIDE=4.5COMPAT` only for the owned private Caspar process. SPX and legacy component launches retain their environment. Inherited case variants of these three variable names are replaced so Windows cannot choose a conflicting duplicate.

Preparation requires a nonempty regular `opengl32.dll` beside the canonical Caspar executable; putting a copy only in a different working directory is insufficient. A missing, empty, directory or symbolic-link library returns the fixed `MESA_RUNTIME_MISSING` boundary error before media staging, listeners or service startup. This presence check does not verify version/hash, loaded-driver identity, complete dependencies, pixels or hardware compatibility. Use the separately pinned and licensed component preparation; Caspar/Mesa/NDI binaries are not bundled here. Actual output from the extracted application still requires Windows software proof, and target Windows10/stadium compatibility remains unverified.
